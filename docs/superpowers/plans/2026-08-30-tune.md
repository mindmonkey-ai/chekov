# `chekov tune` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `chekov tune [NAME]` measures, on this machine, whether flash attention, the KV cache type, the batch size or the ubatch size beats the model's current launch flags, records every trial, and prints the winning argv or `defaults won`.

**Architecture:** A pure core module (`core::tune`) owns the stage plan, argv rewriting, the per-stage verdict, the degenerate rule, the thermal parse and the JSON record; the command module (`commands::tune`) owns the confirm gate, the trial loop through the shared candidate lifecycle, the report and `--apply`. The lifecycle trio `bench` already uses (`launch_candidate` → `ensure_ready` → `teardown_candidate`) moves into `core::bench::candidate` so `bench` and `tune` call one implementation. Measurements reuse `sweep::measure_depth`, `stats::summarize` and `stats::compare`; the record's flag sextet reuses `stamp::flag_value_either`.

**Tech Stack:** Rust 2024 (≥1.88), clap derive, serde/serde_json/toml, thiserror; llama.cpp `llama-server` through chekov's translator; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-08-30-tune-design.md` (§4 stages and verdict, §5 degenerate, §6 thermal, §7 plan, §8 record and apply, §9 report, §10 config, §11 errors).
